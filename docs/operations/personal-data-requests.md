# 個人情報の開示・訂正・利用停止・削除のご請求への対応手順（運営者向け）

プライバシーポリシー（第8条・第9条）に書いた内容を、運営者が実際に行うための手順です。
ここに書いていないこと（対応の期限、専用の窓口など）は、現時点で用意していません。決めたら、プライバシーポリシーと合わせて更新してください。

## 受付

- お問い合わせフォーム（Googleフォーム）または `contact@mrsatto.com` で受け付けます。
- 請求の種類（開示・訂正・利用停止・削除）と、登録しているメールアドレスを確認します。

## 本人確認

- 登録しているメールアドレスから届いた連絡かを確認します。
- 別のアドレスから届いた場合は、登録メールアドレス宛に確認の返信を送り、本人が受け取れることを確認します。
- 確認できない場合は、対応しません（他人の情報を渡さないため）。

## 種類ごとの対応

| 請求 | やること | 場所 |
| --- | --- | --- |
| 開示 | そのユーザーの `auth.users`（メールアドレス・登録日）、`profiles`、`subscriptions`、`terms_consents`、`tool_usage_daily`、`ai_usage_*` の行を確認し、本人に伝える | Supabase ダッシュボード（Table Editor / SQL Editor） |
| 訂正 | メールアドレスの変更などは、Authentication → Users から対応する（現在、画面からのセルフ変更は用意していない） | Supabase ダッシュボード |
| 利用停止 | 有料プランの契約がある場合は、先に契約の扱いを本人と確認する | Stripe ダッシュボード / 本人 |
| 削除 | 原則、ご本人にアカウント画面の「アカウントの削除」をご案内する。ご本人が操作できない場合のみ、下記の手順で代行する | 下記 |

## 削除を代行する場合の注意

1. 有料プランの契約が続いていないか、Stripeで確認する（続いている間は削除しない。先に解約→期間終了後）。
2. Supabase の Authentication → Users から該当ユーザーを削除する。関連する行（プロフィール・契約情報・利用記録・同意の記録）は連鎖して消える。
3. Stripe の顧客・支払い記録は、この操作では消えない。削除するかどうかは、会計・税務上の保存の要否を確認して判断する（現在の方針は未確定）。
4. 実施した事実（日付・請求の種類）だけを、個人情報を含めない形で記録しておく。

## 注意

- 返金は、アカウントの削除では行わない（利用規約 第6条）。
- バックアップ・運用ログに残るデータの保存期間は、利用中のサービスの仕様を確認していない。確認できたら追記する。
