## 最初に（結論）

ファイルのドラッグ＆ドロップに対応しているツールで、ファイル選択欄まで運ばなくても、ページのどこに落としても読み込めるようにしました。

- 共通のファイル選択欄（`FileDropzone`）を1か所変えるだけで、これを使う全ツールに効きます。ツールごとの処理には手を入れていません。
- ファイルをドラッグしている間だけ、ページ全体に「ここにファイルをドロップ」の案内を重ねます。案内はクリックを通すので、ボタン・リンク・入力欄の操作を妨げません。
- 落としたファイルは、欄で選んだときと同じ確認（形式・サイズ・数）と処理に渡します。対応形式・上限は変えていません。
- 外部からのファイルのドラッグだけに反応します。ページ内の文字・画像・リンクのドラッグや、ファイルを含まないドラッグには反応せず、ブラウザの通常の動作も止めません。
- 広告・ダウンロード・課金の制御、プライバシーの方針（ブラウザ内処理・送信なし）は変えていません。
- commit・push・マージ・デプロイは行っていません。ロードマップは変えていません。

### 全画面のドロップをしない場面

- 入力欄が同時に2つ以上出ている画面：どの欄へ渡すか決められないため、全画面のドロップはせず、これまでどおり各欄へのドロップだけにする（例：フォーム→個別PDFでデータの欄が出たあと）。最初の画面で欄が1つだけなら、その欄が受け取る
- 補助的な欄：PDF記入・注釈の画像・印影の欄、シフト表の保存ファイル（JSON）の読み込み（読み込むと入力中の表が置き換わるため、うっかりのドロップを避ける）
- ダイアログ（広告の確認など）が開いている間
- ファイル選択欄がない画面（ホーム・一覧・生成だけのツールなど）

## 4. 仕組み

- `src/lib/drop/page-file-drop.ts`：ページ全体のドロップの受付。ファイル選択欄が「受け取り先」として登録し、受け取り先がちょうど1つのときだけ働く
  - ブラウザのイベントは window で受ける。受け取り先が1つ以上ある間だけ登録し、最後の受け取り先がなくなったら外す（ページの移動・画面の破棄で残らない）
  - 外部のファイルのドラッグか：ドラッグの中身に「Files」があり、かつ、このページの中で始まったドラッグ（dragstart が起きたもの）ではないこと
  - 外部のファイルのドラッグの間だけ、ブラウザの既定の動作（ファイルを開いてページが移る）を止める
  - 欄そのものへのドロップは、欄がすでに処理しているので、二重に渡さない
  - フォルダが含まれるドロップは受け付けず、案内を出す（欄そのものへのドロップでも同じ）
- `src/components/common/page-file-drop.tsx`：受け取り先の登録（`usePageFileDrop`）と、ドラッグ中の案内の表示。案内は画面全体に重ね、点線の枠と「ここにファイルをドロップ」、欄の名前（例：「PDF」「画像（複数可）」）を出す。Mr.Sattoの色・角丸・影の設定を使う
- `FileDropzone`：受け取り先として登録し、受け取ったファイルを、欄へのドロップと同じ `validateAndEmit` に渡す。`pageDrop` で個別に外せる（既定は、ツール間の受け渡しの受け取り欄と同じ）
- 年度カレンダーの予定データ：同じ仕組みで登録し、欄へのドロップと同じ `handleFiles` に渡す（読み込み中は受け付けない）

### ドラッグ中の表示が残らないための対策

- ドロップしたとき（成功・形式違い・フォルダ・エラーのどれでも）に消す
- ドラッグの終了（dragend）で消す
- 画面の外へ出たとき（dragleave で行き先がなく、位置が画面の端）に消す
- ドラッグの通知（dragover）が0.6秒途切れたら消す（Escキーでの中断など、イベントが来ない場合の保険）
- 受付をやめるとき（受け取り先がなくなったとき）にも消す

## 7. 未対応事項・残っているリスク

- 実際のマウス操作でのドラッグは、自動テストではブラウザの仕組み上再現できないため、同じイベント（DragEvent と DataTransfer）を発生させて確認した。実機のブラウザ（Safari・Firefox など）での見え方の確認はしていない（必須ではない）
- フォルダの判定は、ブラウザがフォルダを見分けられる場合（Chrome・Edge・Safari・Firefoxの現行版）に限る
- Escキーでの中断はイベントが来ないため、0.6秒後に表示を消す（その間だけ案内が残る）
- 入力欄が2つ以上ある画面では全画面のドロップをしない（どの欄に入れるかを選ぶ仕組みは作っていない）
- スマートフォン・タブレットはファイルのドラッグ＆ドロップがほぼないため、これまでどおりタップで選ぶ

## Claudeの意見

- 入力欄が2つ以上ある画面では、あえて全画面のドロップをしない設計にしました。間違った欄にファイルが入るより、これまでどおり欄に落としてもらうほうが安全なためです。将来、欄ごとに「この欄へ」を選べる案内（ドラッグ中に欄を大きく表示するなど）を作れば、これらの画面にも広げられます。
- 案内の文言は短くしました（「ここにファイルをドロップ」と欄の名前）。実際の画面で目立ちすぎる・弱すぎると感じたら、色や透明度はすぐに調整できます。
