## 3. 技術的な仕組み（安全な墨消しの方式）

- **範囲を指定したページ**: pdfjs でページ全体を画像（2倍。1辺4,000pxを超える巨大ページは倍率を下げる）にし、canvas上で指定範囲を黒で塗りつぶしてから、JPEG画像だけのページとして新しいPDFに入れる。元のページの文字・画像・図形・フォント・注釈は、新しいPDFに**一切入れない**。黒い四角が元の文字の上にあるのではなく、画像のピクセル自体が黒に置き換わっている。
- **範囲を指定していないページ**: 元のまま `pdf-lib` でコピーする。ただし、リンク・注釈・入力欄（`/Annots`）、ビーズ（`/B`）、サムネイル、`/PieceInfo`、`/AA` は、他のページを参照して**黒塗りするページの元データを持ち込む**恐れがあるため、コピー前に取り除く。
- **孤立データの除去**: 書き出す前に、文書のルートから辿れないデータを削除する（念のための二重の安全策）。
- **書き出し後の確認**: 新しいPDFを開き直し、ページ数が元と同じこと、黒塗りしたページに文字が0であることを確認する。確認できなければダウンロードさせずにエラーにする。
- **座標**: 範囲は「表示されたページの縦横に対する割合（0〜1）」で持つ。拡大・縮小・スクロール・ページ回転が変わっても、同じ場所を指す（pdfjsの表示向きのまま画像にするため、回転ページも一致する）。
- 通信は一切行わない（ブラウザ内処理）。新しい依存ライブラリは追加していない。

### テスト中に発見して修正した問題

3ページ目のリンクが、黒塗りする2ページ目を指しているPDFで、**元の文字が出力ファイルに残る**ことをテストが検出した。原因は、`copyPages` がリンクの行き先（2ページ目）ごとコピーし、ページから注釈を外しても、コピーされたデータが出力に書き出されていたこと。「コピー前に注釈等を取り除く」「孤立データを書き出さない」の2点で解消し、同じテストで再発を防いでいる。

## 4. 対応範囲

| 種類 | 対応 | 備考 |
|---|---|---|
| テキストを含む通常のPDF | 対応 | 指定ページは画像になる。黒塗りしていない文字も、そのページでは選択・検索できなくなる |
| スキャン画像のPDF | 対応 | 画像のピクセルを黒に置き換える。OCR等は使わない（導入しない） |
| テキストと画像の混在 | 対応 | ページ全体を画像にするため、種類を問わず同じ方法で処理できる |
| パスワード付きPDF | 非対応 | 理由を表示して処理しない |
| 壊れたPDF・PDF以外 | 非対応 | 理由を表示して処理しない（内容はエラー文に含めない） |
| 100ページ超 | 非対応 | 上限を表示 |
| 黒塗りできるページ数 | 30ページまで | メモリ使用量を抑えるための上限 |

## 5. 安全性の検証（自動テスト）

- 対象の文字が、文字抽出で取得できない（黒塗りしたページの文字は0）。検索・コピーは、同じ文字データを使うため同じ結果。
- PDFファイルの中身（圧縮の展開・16進数の文字列の復号を含む）に、対象の文字も、黒塗りしたページの他の文字も残っていない。検査方法の正しさも、元のPDFでは見つかることで確認している。
- 黒塗りしたページに、元の画像（PNG）のデータが引き継がれていない（出力の画像はJPEG1つだけ）。
- リンクを通じて黒塗りするページが持ち込まれていない（出力のページは4つだけ）。出力のページに注釈が残っていない。
- 黒塗りの位置が、指定した場所と一致する（結果の画像のピクセルを確認。黒い部分と、元のままの部分）。複数の範囲・複数のページ・拡大後のスクロール・縮小・90度回転ページで確認。
- 範囲を指定していないページの文字が保たれる。元のファイルは変更されない。
- ファイルの内容（対象の文字など）が、自社API・外部へ送信されない。

**検証できていない・保証しないこと**: すべてのPDFでの安全性は保証しない。範囲の指定漏れは、そのまま残る。特殊なPDF（暗号化の一部、PDFポートフォリオ、極端に大きいページ、描画に失敗する独自の表現）は未検証。ブラウザの実機での見た目の確認は、自動テスト（Chromium）の範囲に限る。
