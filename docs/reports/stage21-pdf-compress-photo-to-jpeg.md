# PDF圧縮：JPEG以外で入っている写真のJPEG化 報告書

作成日：2026-11-01（利用者からの依頼「入れられてる写真はJPEGにする形であればいける？」「とりあえずそれを入れてもらえるかな？」による。ファイル名は既存の報告書と重ならないよう stage21 とした）

## 最初に（結論）

PDF圧縮で、JPEG以外の形式（Flate。PNGに近い形式）で入っている写真も、JPEGに作り直して小さくできるようにしました。

- きっかけ：デザインソフトから書き出したLPのPDF（22.53MB）を「20MB以下」で圧縮したところ、画像39,067個のうちJPEGは25個だけで、20.45MBまでしか小さくならなかった
- JPEG以外の画像のうち、写真のような大きな画像（200×200画素以上、かつデータが30KB以上）だけをJPEGにします。小さな部品・アイコンは、JPEGにしてもほとんど小さくならず、輪郭がにじみやすいため、そのまま残します
- 透明度（SMask）・マスクとして使われている画像は、JPEGにしません（JPEGにすると透明の扱いが壊れるため）。透明度を持つ写真は、本体だけをJPEGにし、透明度は別の画像のまま残すので、見た目の透明は変わりません
- 作り直して元より大きくなる画像は、元のまま残します
- 目標のサイズ（MB）を指定する圧縮と、画質を指定する圧縮の両方で働きます。「画像はそのまま」では変えません
- 文字・図形・リンクは変えません（文字の検索・選択もそのまま）。処理はブラウザの中だけで、ファイルを送信しません。新しいパッケージは追加していません
- commit・push・マージ・デプロイは行っていません

## 2. 仕組み（`src/lib/processors/browser/pdf-image-recompress.ts`）

1. PDFの中の画像のうち、透明度・マスクとして使われている画像を先に集め、対象から外します
2. 次の条件をすべて満たす画像を、JPEGにする対象にします
   - Flateだけで縮められている、1色あたり8ビット
   - 色がRGB・グレー（同じ色数のICCBasedを含む）。CMYK・Lab・Indexedは、色が変わるおそれがあるため対象外
   - 200×200画素以上、保存されているデータが30KB以上
   - Decode配列・カラーキーのマスクを持たない
3. データを戻します（ブラウザの機能 DecompressionStream を使い、使えなければ pdf-lib の機能で戻す）
4. 行ごとの前処理（PNGの予測。Predictor 10〜15）がかかっていれば、それを戻します。pdf-lib には、この前処理を戻す機能が無いため、自分で作りました（フィルター5種類：なし・左・上・平均・Paeth）。TIFFの予測など、扱えない形式は対象外にします
5. 画面に出さないcanvasに描き、指定した品質・大きさのJPEGにします。元より小さいときだけ置き換えます

JPEGの画像の作り直し（工程18）にも、同じく「透明度・マスクとして使われている画像は対象外」を加えました（以前は、この区別がありませんでした）。

結果の画面には、「JPEG以外で入っていた写真◯個は、JPEGにしました。」と表示します（1個以上のときだけ）。

## 5. 未対応事項・残っている制約

- 利用者のPDF（LP課題_ナイトセラム.pdf）では、まだ確認していません。写真の多くがJPEG以外で入っていれば20MB以下に届く見込みですが、写真がCMYKで入っている場合などは効果が小さくなります
- 写真をJPEGにすると、輪郭のはっきりした部分（写真の中の文字など）は、品質を下げるとにじみやすくなります
- 画像が多い・大きいPDFでは、目標のサイズに合わせるための試行（最大6回）のたびに作り直すため、時間がかかることがあります
- 透明度（SMask）の画像そのものは小さくしません

## Claudeの意見

- まずは「写真らしい大きな画像だけ」に絞りました。誤ってロゴや図をJPEGにしても、元より大きくなる場合は元のまま残るため、大きな問題にはなりにくいと考えています。
- 実際のPDFで20MBに届かなかった場合は、前に提案した「ページを画像にして、目標のサイズにする」（最後の手段）を足すことを提案します。
