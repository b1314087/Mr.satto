## 1. 実装した機能（事実）

ツール名「領収書・レシートから会計CSV作成」（ID：`receipt-accounting-csv`、カテゴリ：Excel・CSV、プラン区分：standard、処理場所：ブラウザ内）を追加しました。ページは `/tools/receipt-accounting-csv` です。

- JPG・PNG・WebP・PDFを、複数まとめて読み込めます。形式はファイルの先頭のバイトで判定し、拡張子は信用しません。
- 1ファイルずつ順番に処理します。対応外・壊れた・空・大きすぎる・パスワード付きのファイルは、そのファイルだけをエラーにして、ほかのファイルの処理は続けます。
- PDFはページごとに、文字情報があればそれを使い、無い・使えないページだけ画像にしてOCRで読みます。1ページを1書類（1行）として扱います。
- 日付・取引先・合計金額を「候補」として取り出します。複数あって決められない場合は自動で入れず、候補を示して選んでもらいます。
- 確認・修正の一覧：ファイル名（PDFはページ番号つき）、日付・取引先・合計金額の入力欄、状態（未確認／確認済み）、エラー・注意、元の書類の画像（拡大可）、読み取った文字（確認用）、候補ボタン、行の削除、すべて消去（2回押し）、確認済みの一括解除、件数表示（確認済み／未確認）。
- 「確認済みにする」を押した行だけがCSVに出ます。自動では確認済みになりません。値を直すと確認済みは外れます。必須値が不備の行は、確認済みにできずエラーを表示します。
- 確認済みが0件のときは、案内を表示し、ダウンロードボタンを無効にします（見出しだけの空CSVは作りません）。
- 出力前に、出力内容の一覧（プレビュー）と件数を表示します。
- 既存のダウンロードの仕組み（`RewardedDownloadGate`・`downloadBlob`）をそのまま使っています。
- このツールのページでは、ツールページ下の広告枠とフッターの広告枠を出しません。
- 注意文：読み取り結果に誤りがあり得ること、会計ソフト専用ではなく取り込みを保証しないこと、電子帳簿保存法に対応した保存の仕組みではないこと、会計・税務の助言ではないことを、画面とFAQに書きました。

実装しなかったもの（指示どおり）：freee専用CSV、AI抽出、Excel出力、保存用PDF、設定の保存、勘定科目・税区分の自動判定、新しいOCRライブラリ・外部OCR・AI API。

## 3. OCRとPDFの読み取り方法（事実）

- 画像：既存のTesseract.js（自己ホスト、日本語）をそのまま使用。新しいOCRライブラリは追加していません。OCRに渡す画像は「約400万画素・長辺4000px以内、拡大はしない」に縮小します（細長いレシートを潰さないため。既存の長辺2000px固定とは別）。
- PDF：pdfjs-dist（既存）で、ページごとに文字情報の有無を判定。文字情報が使えるページはその文字を座標から行にまとめて使い、使えない（極端に少ない・文字化けが多い）ページはページを画像にしてOCR。文字情報が使えそうでも日付・金額の候補が全く無いページは、OCRでも読んで候補が得られるほうを使います。
- 「文字情報がある」ことを正しさの根拠にはしていません。どの書類も、元の画像と読み取った文字を並べて、利用者が確認する前提です。
- OCRの信頼度（単語の確度）は、値を決める根拠にはせず、低い行から読んだ値に「要確認」の注意を出すためだけに使います（しきい値60は暫定）。
- 抽出の方針：合計は「合計・お会計・お支払・請求金額・税込・TOTAL」などの強い表記の金額がちょうど1種類のときだけ自動入力。小計・消費税・お預り・お釣り・カード・決済番号などの行は除外。日付は有効な日付がちょうど1つのときだけ自動入力（有効期限などは除外、2桁年は候補のみ）。取引先は「株式会社」等の会社名らしい行が1つのときだけ自動入力。それ以外は空欄にして候補を示し、値を作りません。
- 上限（暫定値）：画像1枚15MB、PDF1つ30MB・20ページ（既存OCRと同じ）、一度に30ファイル、画面に並べる書類は60件、画像50メガ画素まで。

## 4. CSVの列と安全対策（事実）

- 列：`日付`、`取引先`、`合計金額`（この順）。日付は `2026/09/15` 形式、合計金額は円単位の整数（税込・税抜の区別なし。書類に書かれた合計金額をそのまま出力）。
- 文字コード：UTF-8（先頭にBOM付き）、改行はCRLF。Excelで開いたときに文字化けしにくくするためで、どの会計ソフトへの取り込みも保証しません。
- 数式対策：取引先が `=` `+` `-` `@`・タブ・復帰で始まるときは、先頭に `'` を付けて出力します（画面にも注記を出します）。
- CSVのエスケープ（カンマ・引用符・改行）は既存の `serializeCsv` が行い、数式対策とは別の処理として分けています。
- 出力前の検証：確認済みの行を再検証し、必須値が不備なら出力せずエラーを出します。
- 取引先の制御文字・見えない文字・改行・タブは除去します。

## 5. ブラウザ内処理・通信の確認結果（事実）

- コード上：新規ファイルに `fetch`、`console.*`、`localStorage` / `sessionStorage` / IndexedDB の使用はありません（検索で確認）。読み取った内容・ファイル名はコンポーネントの状態（メモリ）にだけ置き、画面を閉じる・すべて消去・行の削除で、プレビュー用の画像URLを解放し、OCRのWorkerを終了します。
- エラー文には、ファイル名・書類の内容を含めていません（ファイル名は、利用者自身の画面の一覧にだけ表示）。
- テスト（Playwright）：画像・PDFを読み込み、取引先を入力してCSVを出力するまでの間、取引先の固有文字列・ファイル名・金額・PDFの中身の文字が、自社API・外部ホストのどちらへの通信にも含まれないこと、20KB超のPOST/PUT/PATCHが無いことを確認し、合格しました。
- 注意：OCRの言語データ・WASMは、既存どおり自己ホストのファイルを取得します（読み込み時の取得であり、利用者のデータの送信ではありません）。

## 7. 既知の制限・未解決（前提・未確認を含む）

事実として分かっている制限：

- OCRの読み取り精度は評価していません。画面テストはOCRの経路が動くことだけを確認しており、精度は主張できません（工程9で評価）。
- パスワード付きPDF・21ページ以上のPDFのエラーは、コードで対応していますが、自動テストは書いていません（テスト用の暗号化PDFを用意していないため）。
- 共通のファイル選択部品は、対応外の形式が1つでも混ざると全部を断る作りのため、このツールでは `accept` を渡さず、ファイルごとにエラーにしています。副作用として、ファイル選択ダイアログが形式で絞り込まれません。
- 日付の入力欄はブラウザ標準の `type="date"` のため、表示の並び（年月日／月日年）はブラウザの言語設定に従います。
- 出力できるのは日付・取引先・合計金額の3項目だけです。税率別の内訳・インボイス番号・勘定科目・税区分・摘要は扱いません。
- 同じ行（日付・取引先・合計金額が同じ）は、注意を出すだけで、自動では削除しません。

私が決めた暫定値（前提）：

- 各種の上限、OCRに渡す画像のサイズ、OCR信頼度のしきい値60。いずれも根拠となる実測はまだありません。
- 合計金額は税込・税抜を区別せず、書類の「合計」表記の金額を使う方針です。

広告まわりの注意（要判断）：

- ツールページ下とフッターの広告枠は、このツールでは出しません。ただし、サイト全体で読み込まれるAdSenseのスクリプト（広告IDが設定されている場合のみ）は、このページでも読み込まれます（利用者のデータは含みません）。AdSense側で自動広告をオンにしている場合は、このページにも広告が挿入され得るため、公開前に設定を確認してください。
- 広告機能（`featureFlags.ads`）が将来オンになり、無料プランのダウンロード前に広告の確認画面を出す仕組みが有効になると、このツールのCSVダウンロードにも適用されます。今は本番で広告機能がオフのため影響はありません。このツールだけ除外するかは、方針を決めてから対応が必要です。
