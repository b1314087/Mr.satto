## 最初に（結論）

ツールの処理結果を、受け取れる別のツールへそのまま渡せる共通の仕組みを実装しました。

- 結果のダウンロードボタンの下に、全ツール共通の「ほかのツールで使う」を出します。押すと、その結果を受け取れるツールだけが候補に出て、選ぶとそのツールが結果を読み込んだ状態で開きます。

- 受け渡しも、ダウンロードと同じ広告の確認を通ります（受け渡しで広告の確認を回避できません）。
- 47ツールに設定しました（受け取り42・送り出し43）。設定のないツールは、これまでどおり単独で使えます（受け取りも送り出しもしません）。

## 3. 実装した仕組み

### 3-1. 設定（受け取り・送り出しの管理）

- `src/lib/handoff/types.ts`：受け渡しの型。ツールごとに `role`（generate／edit／convert／inspect）、`receive`（受け取れる種類・数・1ファイルの上限MB）、`send`（送り出しうる種類）を持つ
- `src/lib/handoff/config.ts`：全ツール分の設定の唯一の場所。ツール一覧（`data.ts`）を組み立てるときに各ツールの `handoff` に入る（`Tool` 型に `handoff` を追加）
- 未設定のツールは、受け取りも送り出しもしない（無条件に許可しない）
- 種類：PDF・PNG・JPG・WebP・GIF・CSV・TSV・テキスト・Markdown・JSON・Excel・Word・PowerPoint・ZIP。ZIP作成・ハッシュ計算だけは「どの種類でも」

### 3-2. 方向の制御

- 送り元が `send` を、送り先が `receive` を宣言しているときだけ、送り元 → 送り先 が成り立つ。逆向きは、それぞれの宣言しだい
- 生成ツール（二次元コード・見積書・注文書の一体作成・年度カレンダー・シフト表）は `receive` を持たない（テストで確認）。調べるツール（外字チェック・ハッシュ）は `send` を持たない
- 自分自身・自分の総合ツールへの受け渡しは出さない

### 3-3. 候補の判定（`src/lib/handoff/targets.ts`）

結果のファイルそのもので、次をすべて満たす送り先だけを候補に出します。

1. 送り元が送り出しを設定している
2. 送り先が受け取りを設定している（一覧に出るツール・実装あり・利用可能）
3. すべてのファイルの種類が、送り先の受け取れる種類に含まれる
4. ファイル数・1ファイルのサイズが上限以内（0バイトは渡さない）
5. 利用者のプランで送り先を使える
6. 自分自身ではない

種類は、拡張子だけでなくファイルの先頭のバイトでも確かめます（`src/lib/handoff/file-kind.ts`）。Excel・Word・ZIPはZIP形式であることを確かめてから拡張子で区別します。判別できないファイルは「どの種類でも」受け取るツールにだけ渡せます。

### 3-4. 結果の受け取り方（各ツールに専用コードを書かない）

- 「ほかのツールで使う」を押すと、そのツールのダウンロード処理を「受け取りモード」で実行し、`downloadBlob()` に渡された結果を保存せずに受け取る（`src/lib/handoff/capture.ts`）。ダウンロードと同じファイル・同じ名前になる
- 結果にMIMEタイプがないときは、判別した種類のものを補う

### 3-5. ブラウザ内の一時置き場（`src/lib/handoff/store.ts`）

- ブラウザのメモリ上に置く。サーバー・localStorage・sessionStorage・IndexedDB・Cookie には保存しない
- 識別子：ランダムなUUID。URLには `?handoff=<UUID>` だけを付け、受け取り側はすぐにURLから消す
- 有効期限：10分。受け取りに成功したら置き場から消す（1回だけ）
- 古いものの掃除：置く・取り出すたびに期限切れを消す。残すのは新しいものから3件まで、合計600MBまで
- 不正な識別子・存在しない識別子・宛先違いは安全に断る（宛先違いは消さない）

### 3-6. 画面

- 送り出し（`src/components/handoff/handoff-send.tsx`）：ダウンロードボタンの下に「ほかのツールで使う」。押すと候補の一覧（ツール名）と結果のファイル名・サイズを出す。候補がない場合は理由（形式・数・サイズ）を出す。受け渡せる候補が一度も出ないツールでは、ボタン自体を出さない
- 受け取り（`src/components/handoff/handoff-provider.tsx`）：ツールページが各ツールを囲む。受け取ったファイルは、ページで最初に表示された共通のファイル選択欄が、利用者が選んだときと同じ確認（形式・サイズ・数）を通して読み込む。成功すると「〇〇の結果を受け取りました：ファイル名」を表示
- 失敗時の案内：見つからない（再読み込み・別タブ・古いURL）、期限切れ、形式・サイズ・数が合わない、この画面で受け取れない、プランで使えない、メモリが足りない。いずれも、元のツールでは結果をそのままダウンロードできる
- 補助的なファイル選択欄（PDF記入・注釈の画像・印影の欄）は受け取らない設定にした（`acceptHandoff={false}`）

## 4. 受け渡しの設定（47ツール）

| 区分 | 受け取る（種類） | 送り出す |
|---|---|---|
| 画像の編集（リサイズ・圧縮・トリミング・回転反転・グレースケール・メタデータ削除・ウォーターマーク・モザイク・SNSサイズ） | PNG・JPG・WebP（1つ・50MB） | 画像 |
| 画像形式変換 | PNG・JPG・WebP・GIF（20個まで・50MB） | 画像・ZIP |
| PDF修正・黒塗り・メタデータ削除・用紙サイズ・余白トリミング | PDF（1つ・50MB） | PDF |
| PDF圧縮 | PDF（1つ・100MB） | PDF |
| PDFパスワード保護 | PDF（1つ・100MB） | 送り出さない（他のツールで開けないため） |
| PDF編集（総合） | 受け取らない（開いた直後が「結合」のため） | PDF・ZIP |
| 画像→PDF | 画像（20個まで） | PDF |
| PDF→画像／テキスト／Word／Excel、OCR、Word→PDF、Excel→PDF | 各入力形式 | 各出力形式 |
| Excel/CSV変換（総合）・CSVの編集・Excelの編集・Wordの編集・PowerPoint白黒反転 | 各形式 | 同じ形式（Excel/CSV変換はCSV・Excel） |
| 外字・特殊文字チェック、ファイルハッシュ | 各形式／どの種類でも | 送り出さない（結果は元のファイルではない） |
| ZIP作成 | どの種類でも（20個まで・200MB） | ZIP |
| ZIP解凍 | ZIP | 送り出さない |
| 生成：二次元コード、見積書・注文書の一体作成、年度カレンダー、シフト表 | 受け取らない | PNG／PDF／Excel・PDF／PDF・Excel・CSV |

受け取りの上限・形式・複数可否は、受け取るツールのファイル選択欄と同じ値で、テストで照合しています。

### 設定しなかった主なツールと理由

- 音声・動画のツール：処理が重く、入力の条件（長さ・形式）がツールごとに細かいため。必要になったら同じ設定に足すだけで対応できる
- PDF記入・注釈、PDFページ番号、PDF透かしの個別ページ：同じ機能を持つ「PDF修正」が受け取るため（候補が重複しないように）
- 生成ツールのうち、名簿などのデータを読み込むもの（封筒宛名・整理券・名簿テンプレート・席次表など）：他のツールの結果を入れる用途が確認できないため受け取らない。結果の送り出しは、出力の確認ができていないため未設定
- 背景除去、画像結合・レイアウト・余白と文字・分割・証明写真・画像補正：入力が複数の前提や、補助的な入力欄があるため
- 経理（領収書→会計CSV）、記入済みPDF→Excel、フォーム→個別PDF、電子印鑑：独自の利用制限や、複数の入力欄があるため
- 文字・数値などの入力だけのツール（文字数カウント・JSON整形など）：ファイルを受け取らないため

## 5. ダウンロード・広告・課金への影響

- ダウンロードボタン・保存の動作は変えていない。受け取りモードの間だけ、`downloadBlob()` は保存せずに結果を受け取る
- 受け渡しは、ダウンロードと同じ関所（`runWithDownloadAccess`）を通す。無料プランで広告の確認が必要なときは、受け渡しの前に同じ確認画面が出る（キャンセルすると移動しない。テストで確認）
- 受け渡しボタンを押しただけでは、新しい広告は出さない（広告の確認が必要なときに、ダウンロードと同じ確認が出るだけ）
- 送り先の利用制限は、送り先のページの `ToolAccessGate` がこれまでどおり判定する。使えないツールは候補に出さず、URLで直接開いても受け取らずに案内する
- 広告の設定値・プラン・料金・課金の設定は変えていない

## 8. 未対応事項・残っているリスク

- 設定したのは47ツール。残りのツールは受け渡しの対象外（上の4. のとおり、設定を足せば対応できる）
- PDF編集（総合）は受け取らない。ページの回転などへ渡すには、受け取ったときに最初に出す機能を選べるようにする必要がある
- ZIPは展開して渡さない（展開するには、パス・ファイル数・合計容量の確認を受け取り側ごとに用意する必要がある）
- 受け渡しはページ全体の再読み込みをしない画面の移動で行う。再読み込み・別タブでは引き継がれない（案内を出す）
- 結果が複数のダウンロードボタンに分かれているツール（シフト表・年度カレンダー）では、ボタンごとに「ほかのツールで使う」が出る
- 広告の確認画面のボタン名は「ダウンロードする」のまま（受け渡しのときも同じ画面を使うため）。確認画面の一覧には「〇〇で開く」と出る
- 受け渡しの判定は画面上の制御。ブラウザ内で完結する以上、開発者ツールなどでの回避を完全には防げない（ダウンロードの広告確認と同じ）
- PDF編集・PDF修正のよくある質問（工程15で「ダウンロードしてからPDF修正で選ぶ」と案内）は今回は変えていない。受け渡しで直接開けるようになったため、文言の見直しを提案する

## Claudeの意見

- 受け渡しを「ダウンロードと同じ結果を、保存せずに受け取る」形にしたので、各ツールに専用コードを足さずに済みました。今後ツールを増やすときも、`config.ts` に1行足し、テストの照合表に1行足すだけで受け渡しに対応できます。
- 候補が多いと選びにくくなります（PDFを送ると十数個出ます）。次に手を入れるなら、よく使う送り先を先頭に出す並び順（例：同じカテゴリを先に）を勧めます。
- PDF編集が受け取れないのは不便です。受け取ったときに「回転・ページ削除など、どの操作で開くか」を選べるようにすると、PDFまわりの行き来がかなり楽になります。
- 工程15で書いた「ダウンロードしてからPDF修正で選んでください」というよくある質問の答えは、今回の受け渡しで古くなりました。「ほかのツールで使う」から開ける旨に直すことを提案します（今回は指示の範囲外のため変えていません）。
